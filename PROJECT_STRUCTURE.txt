# Cấu trúc MediCare Clinic

Frontend: React 18 + TypeScript + Vite. Backend: Java 17 + Spring Boot 3.1.5 + Spring Data JPA. Database chạy ứng dụng: MySQL 8. Test tích hợp dùng H2 riêng.

## Thư mục

- backend/src/main/java/com/medicare/clinic/controller: HTTP API và entry SPA.
- service/interfaces, service/impl: nghiệp vụ và transaction.
- service/PaymentAccess, service/PrescriptionAccess (khi tích hợp nhánh quyền): kiểm tra session và quyền trên tài nguyên.
- repository, entity: truy vấn và ánh xạ MySQL bằng JPA.
- dto/request, dto/response: dữ liệu API, không trả entity nhạy cảm.
- payment: abstraction gateway và VNPay Sandbox.
- backend/src/test: unit, controller và integration test; backend/target chỉ là kết quả build.
- frontend/src/App.tsx: định tuyến. main.tsx: khởi động React.
- frontend/src/pages, components, contexts, hooks: màn hình và UI dùng chung.
- frontend/src/services, types, utils: HTTP, kiểu dữ liệu và tiện ích.
- frontend/tests: Node test runner và React test renderer.
- database: schema v1.2, seed và migration chạy tay.
- docs: hướng dẫn chạy/kiểm thử và ghi chú thay đổi. context và tests ở root chỉ có placeholder; không phải bộ test đang chạy.

## Luồng dữ liệu

React → Controller → Service → Repository/JPA → MySQL. Backend kiểm tra quyền, trạng thái, dữ liệu và giá. Frontend gọi /api cùng origin; Vite chuyển tiếp tới backend khi phát triển. Danh sách hóa đơn bệnh nhân được ánh xạ trong service.

Các vai trò: LE_TAN, DIEU_DUONG, BAC_SI, THU_NGAN, BENH_NHAN. Session AUTH_USER là nguồn danh tính. Password dùng BCrypt. VNPay đã có implementation Sandbox; chưa có bằng chứng rằng tất cả môi trường public/IPN đều được nghiệm thu.

## Chạy và kiểm tra

Xem README.md, docs/HUONG_DAN_CHAY_LOCAL.md, backend/CONFIGURATION.md và DEPLOYMENT.md. Schema/seed được nạp vào DB demo sạch; Hibernate validate, không tự migrate/seed. Không nạp script bổ sung trên dữ liệu cần giữ.

Backend: mvnw.cmd clean verify (Windows) hoặc bash ./mvnw clean verify. Frontend: npm ci, npm test, npm run lint (sau tích hợp nhánh lint), npm run build. Số test và kết quả xem output của lần chạy, không dùng bảng PASS tĩnh trong tài liệu.

## Bàn giao

Có source cho đặt lịch, tiếp nhận, sinh hiệu, khám, kê đơn/dị ứng/in đơn, hóa đơn/thanh toán/doanh thu và hồ sơ y tế cá nhân. Mức hoàn thành từng UC cần đối chiếu acceptance criteria và kiểm chứng thực tế. SRS/ERD/use-case chính thức cần bàn giao riêng nếu môn học yêu cầu; folder docs hiện không chứa đầy đủ các tài liệu đó.

Không commit node_modules, target, dist, log, cookie, mật khẩu DB hay khóa gateway. Giữ lockfile, wrapper và file cấu hình mẫu. Chỉ commit/push/mở PR/merge khi được yêu cầu; các nhánh sửa lỗi độc lập cần review trước tích hợp develop.
